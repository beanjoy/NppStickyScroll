## 停止滚动后闪烁的复现与修复

旧逻辑将每个 `SC_MOD_CHANGEFOLD` 都当成当前固定内容失效。Notepad++ 采用空闲着色，大文件停止滚动后仍会持续计算后方折叠层级；这些通知使插件反复清空和恢复未改变的祖先行，虽然高度不变，仍有空白帧。

同一自然着色测试在修复前的结果见 `flicker-before-results.txt`：静止约 2 秒期间父级被清空 24 次，绘制 34 个空白帧，高度变化 0 次。修复后的完整回归中，测试开始时仅完成 444,424 / 5,138,958 字节着色，静止采样结束时后台完成全文着色，三个计数均为 0；随后的 60 次滚动同样均为 0。计数来自真实固定区窗口的绘制入口和生产更新路径，测试插桩不编入正式 DLL；这不是桌面视频／物理鼠标验收。

专项复现可在 PowerShell 中设置 `$env:NPP_STICKY_LARGE_ONLY='1'` 后运行 `tests/Run-HostTests.ps1`，结束后用 `Remove-Item Env:NPP_STICKY_LARGE_ONLY` 恢复。完整回归默认也包含该场景。旧性能测试先完成全文着色，不能覆盖这条后台通知路径。

## 性能测量

测试构造一个 150,000 条数据、约 150,078 行的 JSON 文档。宿主已完成词法着色，再从开头直接跳到第 140,000 个文档行：固定祖先在约 **398 ms** 后观察到（测试每 200 ms 左右观察一次，数字包含观察等待）。准备期间固定区隐藏，索引按时间片续接，不强制插件全文解析。该冷跳耗时不能与缓存后的滚动耗时混为一谈。

索引完成后，在同一真实宿主上连续执行 1,000 次“设置视口首行 + 同步固定区更新”，再关闭插件执行同样的滚动调用：

| 指标 | 启用 | 关闭 |
| --- | ---: | ---: |
| 中位数 | 0.3983 ms | 0.4894 ms |
| p95 | 0.7042 ms | 1.0748 ms |
| 最大值 | 2.8318 ms | 2.4736 ms |

第二组构造 256 段深度 1–8 的 JSON，共约 15.7 万行。索引完成后跳到每一段内部，执行更新并同步绘制正文、固定区和滚动条，256 次滚动中固定区高度改变 96 次。关闭插件后再执行相同的滚动与正文绘制：

| 指标 | 启用，含更新与绘制 | 关闭，含绘制 |
| --- | ---: | ---: |
| 中位数 | 16.6742 ms | 16.6800 ms |
| p95 | 17.8123 ms | 17.3312 ms |
| 最大值 | 19.4270 ms | 17.8901 ms |

这些数据说明本机两类输入上的附加开销较小，不能把采样中的较小数字解释为插件让编辑器更快。第一组不强制完整绘制；第二组包含窗口同步绘制，但**仍不等同于桌面合成帧率、输入到屏幕延迟或物理拖动体验**。初次载入、宿主着色不计入；跨机器和更复杂的文件应重新测量。

## 已经实现但未完整验证

- 实际鼠标拖动滚动条、滚轮连续滚动、拖选、实际鼠标单击与完整视觉体验：上一版独立窗口捕获及重新选择窗口重试返回 `window capture timed out: timed out waiting on channel`，本次未补做桌面视频验收。宿主内向真实 `SCROLLBAR` 发送按下消息仍未能启动鼠标捕获，原生拖动循环探测明确记录 `SKIP`，未把它计作通过。滚动条几何、范围冻结、命中和导航使用真实宿主消息及状态断言验证。
- DPI 变化消息处理与按窗口 DPI 计算字体已实现；未实际把窗口跨不同 DPI 的显示器移动。
- 固定内容的深浅主题跟随已通过编辑器样式 API 验证；独立滚动条的主题应用已实现，但未人工操作 Notepad++ 设置页切换主题并检查控件的全部绘制细节。
- 字体字号通过宿主 API 验证；未覆盖每种可变宽字体、复杂文字、字体回退和 DirectWrite 抗锯齿差异。
- 未验证 Windows 11、其他 Notepad++ 版本、其他修改编辑器布局的插件、水平排列双视图、分割条拖动和长期 GDI 资源压力；配置保存和重新启用已测试，退出并重新启动整个宿主后的配置恢复未单独自动测试。

## 暂未支持

XML 多行标签的语义起始位置修复、XML 最后一行缺少后继层级时的推断、同一行多个开闭结构的字符级语义；独立 token 字体／背景、选择与搜索标记的复制；VS Code 推挤动画；x86/ARM64；其他语言；无障碍树中的固定行导航。没有实现面包屑、树、格式化、校验等额外功能。

插件管理的名称仍是 `NppStickyScroll.dll`：已核对 v8.9.1 的 `pluginsAdmin.cpp`，未匹配官方插件目录的插件直接采用文件名；版本资源不会改变这个名称。当前没有官方目录收录，也没有修改宿主或官方列表的私有状态。

## 建议的人工验收

1. 用新的便携版安装正式 `dist/NppStickyScroll.dll`，打开 `samples/DeviceLog.json` 和 `.xml`，保持光标不动，滚动到各结束边界再滚回文件开头。
2. 单击每条固定行，核对状态栏源行；在正文选择、输入、撤销，确认焦点和选择不受更新影响。
3. 折叠／展开、启用换行，打开 `Wrapped.json` 与 `Deep.json`；检查部分父行仍可见和超过 5 层的情况。
4. 在“设置...”中分别选择 3、8 行及两种保留策略，检查行号、顺序和取消行为；克隆、切换和关闭副视图，拖动分割线；切换字体、主题、DPI，观察固定区与正文是否对齐。
5. 打开 `DragLevels.json`，拖住右侧滚动条跨越不同层数和文件开头，检查固定区高度在释放前改变，而右侧轨道不跳；在文件末尾释放，检查位置没有异常跳转。生成并打开 `Large.json`，长时间滚轮滚动，拖动滑块到超过 65,535 行的远处，并在文件开头编辑后回到远处。重复取消拖动、双视图和深浅主题场景。
6. 关闭菜单开关、重启，确认状态保存；再次开启，最后关闭宿主并卸载。
7. 在“关于...”和 Notepad++ 的“调试信息”中检查版本；改变 JSON/XML 的字段、标签和属性颜色，检查固定行同步配色，顶部边框不压住第一行。
8. 重新打开 `Large.json`，立即滚到有父级的位置并停止，观察后台着色期间固定行是否稳定；继续滚动、停止，再编辑父级，确认不闪烁且显示的新内容正确。

## 文件格式

修改前记录了相关源码、测试、构建配置、文档及校验文件的格式基线：UTF-8 无 BOM、纯 LF、保留文件末尾换行；修改后继续保留。新增修复前的测试日志使用相同格式。官方 SDK 未修改。逐文件检查统计 CRLF、裸 LF、裸 CR，可识别混合换行，结果见 `file-format-results.txt`。未发现需要恢复的格式变化。
