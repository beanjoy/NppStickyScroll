# 验证记录

日期：2026-11-11。环境：Windows 10 x64，MSVC 19.44.35228 / Visual Studio 2022，Windows SDK 10.0.26100.0，CMake 3.26.4，官方 Notepad++ 8.9.1 x64 便携版。

没有操作或安装到用户日常 Notepad++。官方便携 ZIP 的 SHA-256 为 `96d39a00d8264ba652a519063313cf3f9f3a1e6cb99f74c7e9c3cecd9ffae989`，已与官方校验文件比对。

## 已经实现并验证

- 正式 x64 Release DLL 构建成功，150,528 字节，6 个官方插件导出入口齐全，仅依赖 Windows 系统 DLL；在另一个全新便携实例中确认正式 DLL 已加载。8 项祖先索引检查通过。
- 真实便携宿主中 **50 项集成检查全部通过**，原始记录见 `host-results.txt`，可通过 `tests/Run-HostTests.ps1` 复现。
- JSON/XML 滚动上下文；滚动时光标停在文件开头仍得到正确父级；文件开头、结束括号／标签边界、空文档、无折叠属性、非支持语言。
- 最近 5 层及从外到内顺序；折叠起始行仍有自动换行片段可见时不重复；6,000 字节父行安全处理。
- Win32 非客户区命中和点击消息准确导航源行；点击后源行不再被固定区重复显示。
- 宿主编辑区外部矩形保持不变；客户区顶部确实在固定行下方，客户区高度按固定区高度减少。自动更新不改变焦点、光标、选区和文档修改状态。
- 插入、撤销、折叠／展开、水平滚动、文件／语言切换、开关恢复、15 万行文件编辑后的失效重建。
- 克隆到双视图后两个视图使用各自滚动位置；关闭副视图后清除其固定区域。
- 改变窗口大小、编辑器 zoom、默认字体、分数字号和颜色后，固定区数据、字体尺寸和高度正确更新。
- 对 XML 多行起始标签不确定的 fold header 及注释折叠，保守跳过，未显示猜测行。
- 所有非空 JSON 示例及 XML 示例经独立解析检查有效；空文件作为边界输入单独保留。
- 用真实编辑 HWND 的 `WM_PRINT` 检查了固定区的 GDI 绘制结果：内容、缩进、暗色背景和分隔线正确。该路径不能捕获 DirectWrite 正文，因此这不是完整桌面截图。

## 性能测量

测试构造一个 150,000 条数据、约 150,078 行的 JSON 文档。宿主已完成词法着色，再从开头直接跳到第 140,000 个文档行：固定祖先在约 **221 ms** 后观察到（测试每 200 ms 观察一次，数字包含观察等待）。准备期间固定区隐藏，索引按时间片续接，不强制插件全文解析。

索引完成后，在同一真实宿主上连续执行 1,000 次“设置视口首行 + 同步固定区更新”，耗时：

| 指标 | 耗时 |
| --- | ---: |
| 中位数 | 0.6267 ms |
| p95 | 1.1455 ms |
| 最大值 | 16.3735 ms |

这是本机该输入上的插件更新路径测量，包含宿主滚动消息开销，**不等同于完整屏幕绘制帧率或手动滚轮体验**。初次载入和 Scintilla 自身着色耗时不计入；其他机器和文件应重新测量。

- 字体字号通过宿主 API 验证；未覆盖每种可变宽字体、复杂文字、字体回退和 DirectWrite 抗锯齿差异。
- 未验证 Windows 11、其他 Notepad++ 版本、其他修改非客户区的插件、水平排列双视图、分割条拖动和长期 GDI 资源压力。

## 暂未支持

XML 多行标签的语义起始位置修复、XML 最后一行缺少后继层级时的推断、同一行多个开闭结构的字符级语义；逐字符语法着色；VS Code 推挤动画；x86/ARM64；其他语言；无障碍树中的固定行导航。没有实现面包屑、树、格式化、校验等额外功能。

## 建议的人工验收

1. 用新的便携版安装正式 `dist/NppStickyScroll.dll`，打开 `samples/DeviceLog.json` 和 `.xml`，保持光标不动，滚动到各结束边界再滚回文件开头。
2. 单击每条固定行，核对状态栏源行；在正文选择、输入、撤销，确认焦点和选择不受更新影响。
3. 折叠／展开、启用换行，打开 `Wrapped.json` 与 `Deep.json`；检查部分父行仍可见和超过 5 层的情况。
4. 克隆、切换和关闭副视图，拖动分割线；切换字体、主题、DPI，观察 fixed area 与正文是否对齐。
5. 生成并打开 `Large.json`，长时间滚轮滚动，拖动滚动条到远处，并在文件开头编辑后回到远处。
6. 关闭菜单开关、重启，确认状态保存；再次开启，最后关闭宿主并卸载。

## 文件格式

初始工作目录为空，无原有项目文件需要改写。新建源码、脚本、文档、示例使用 UTF-8 无 BOM、LF；空示例没有字节。官方 SDK 文件保持原始字节，已通过 SHA-256 对照下载源确认。逐文件检查统计 CRLF、裸 LF、裸 CR，可识别混合换行，结果见 `file-format-results.txt`。未发现需要恢复的格式变化。
